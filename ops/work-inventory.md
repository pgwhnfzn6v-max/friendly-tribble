# 業務一覧（引合 → 請求 → マニュアル化）

解体・専門工事の業務を、案件が流れる順に11フェーズ・58業務へ分解したもの。

**用途は3つ兼ねている。**
1. 業務の棚卸し（誰が何をやっているかの可視化）
2. マニュアル化の優先順位づけ
3. 記事・動画のネタ台帳（`content/` と対応）

## この一覧の作り方（＝ここは要確認）

`estimate-sinwa-canopy.xlsx`（21項目・5工種）、`数量根拠` シート、`demolition-plan-*.html`（rev.4 まで改訂）、`photo-sheet*.html` から**実際にやっている工程を読み取って組み立てた**。読み取れなかった部分は解体・専門工事の一般的な流れで補っている。

**次の8点は推測が入っているので、実態と違えば直してください。**

| # | 推測している点 |
|---|---|
| 1 | 元請経由と直請けの両方があるか（見積の立会いに元請担当が入っているため元請案件と判断） |
| 2 | 請求書の作成方法（会計ソフト／Excel／手書き） |
| 3 | 案件別の原価集計をやっているか、やっているなら何で |
| 4 | 協力会社への発注・支払の流れ |
| 5 | 施工写真の管理方法（`photo-sheet.html` は印刷用。台帳としての保管先は不明） |
| 6 | マニフェストの運用（紙／電子） |
| 7 | 建設業許可の区分と、対応できる工事規模の上限 |
| 8 | 実績歩掛を蓄積しているか（C4 の単価の根拠） |

## 凡例

**AI適用度**
- ◎ 自動化してよい（機械的作業。人が触る価値がない）
- ○ AIに下書きさせて人が確認（10〜15分の監修が前提）
- △ 部分的・条件付き（形式は任せられるが判断は人）
- ✕ 人／有資格者のみ（責任が移せない）

**マニュアル優先度** … 頻度 × 属人度 × 抜けたときのコスト
- **A** すぐ作る　**B** 半年以内　**C** 当面は不要

**記事** … ● は `content/` の記事・動画ネタになるもの

## マニュアル化の進め方

### 順番は「事故コストが高い順」

書きやすい順に作ると、書きやすいものだけが揃って終わる。次の3群に分ける。

**第1群：抜けると法令・金銭の事故になる（6本）**
- H3 マニフェスト返送の期限管理
- E3 事前調査結果の報告
- E5 道路使用許可の申請
- D4 契約書面の法定記載事項チェック
- G6 変更・追加の記録
- J1 出来高・変更精算

**第2群：属人化していて、他の人が代われない（6本）**
- B1 現調準備チェックリスト
- B2 実測の手順（何を必ず測るか、測れない時どうするか）
- B7 現調メモの整理
- C1 数量根拠の作り方
- C3 内訳項目の展開
- C5 別途工事・確認事項の書き方

**第3群：頻度が高く、時間を食っている（6本）**
- F1 施工計画書
- F2 安全書類
- G4 施工写真の撮り方
- I2 完了写真の整理
- J2 請求書
- J5 原価集計

### 粒度は「1本＝A4で1〜2枚」

手順書を大作にすると、書くのも読むのも続かない。1業務1本、A4で1〜2枚。項目はこの5つに固定する。

```
1. いつやるか（トリガー）
2. 何を用意するか（インプット）
3. 手順（番号付き。判断が要る箇所は「※」で分岐を書く）
4. 何ができたら完了か（アウトプット）
5. よくある失敗（自社で実際に起きたもののみ）
```

**5番目が一番価値がある。**一般論の失敗例は要らない。実際にやらかしたことだけを書く。

### マニュアルは、そのまま記事になる

これが今回いちばん効く点です。

上の5項目のうち、**1〜4を匿名化すれば手順記事**、**5がそのまま「つまずき」の記事**になります。`content/FORMAT.md` の記事＝台本フォーマットに、ほぼそのまま流し込める。

つまり **マニュアル化とコンテンツ化は別作業ではなく、同じ作業の内向き／外向き**です。社内向けに1本書けば、公開用が1本できる。逆に記事を書けば社内マニュアルが1本増える。これが、本業を持っている人が発信で有利になる構造そのものです。

ただし公開時は `content/README.md` の公開前チェック6項目を必ず通すこと。特に匿名化（発注者名・所在地・立会者名）と、法令記述を断定しないこと。
