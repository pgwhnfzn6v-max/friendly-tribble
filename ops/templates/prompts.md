# 業務別プロンプト集

> `ops/work-inventory.md` で **◎／○** に分類した業務について、そのまま貼って使える指示文。
> 業務No. と対応している。

## 共通の前置き（毎回、先頭に入れる）

```
あなたは解体・専門工事の実務を補助するアシスタントです。次のルールを厳守してください。

1. 値が確定していない項目は推測で埋めず、空欄のまま残し、末尾の「確認事項」リストに追加すること。
2. 法令の適用可否・届出要否・石綿の含有判定は断定しないこと。「〜に該当する場合は」という条件形で書き、
   最終判断は有資格者と所轄官庁に委ねる旨を明記すること。
3. 単価・金額は、こちらが提示した値のみを使うこと。相場や一般的な金額を持ち出さないこと。
4. 出力に含めた数値は、どの入力値から計算したかを式で示すこと。
```

**3番目が特に重要。**自社の歩掛と協力会社の単価は競争力そのもので、一般論で置き換えた瞬間に赤字案件になる。

## B7 現調メモの整理

```
現地調査の書込み図面から拾った情報を渡します。これを次の3つに分類して表にしてください。

(a) 実測値 …… 実際に測った数字
(b) 聞取り値 … 立会いで聞いた情報
(c) 仮定値 …… 測れなかったため仮に置いた数字（理由も併記）

各項目に記号（m1, m2, ...）を振り、単位を揃えてください。
(c) は必ず「※未測定。◯◯と同等と仮定 → 要確認」と備考に書いてください。

【書込み内容】
（ここに貼る）
```

## C1 数量根拠の作成

```
上で整理した実測値から、数量計算式を組み立ててください。

・計算結果の数字ではなく、「記号を使った式」の形で出すこと（例：Q1 = m1 × m2）
・仮定値を使っている式には、その旨を明記すること
・面積・延長・重量それぞれについて、単位を明示すること
・最後に「仮定値が外れた場合、どの数量がどれだけ動くか」を試算してください
```

**最後の1行が効く。**「未測定が2箇所あります」より「この2箇所次第で撤去面積が1割動きます」のほうが、発注者に先行実測の判断をしてもらえる。

## C3 内訳項目の展開

```
次の工事条件から、見積内訳の項目を展開してください。
工種は Ⅰ仮設 / Ⅱ事前調査 / Ⅲ撤去 / Ⅳ運搬・処分 / Ⅴ諸経費 の5分類とします。

重視してほしいのは、撤去そのものではなく「条件にぶら下がって発生する費用」の抜けです。
例：営業中 → 車両移動・場内調整 ／ 道路側の作業 → 道路使用許可・歩行者誘導員

各項目に「仕様・摘要」と「備考」を付け、単価と金額は空欄にしてください。

【工事条件】
・撤去対象：
・施工条件（営業中か、足場工法、道路側か）：
・材質・下地：
・撤去後の状態：
```

## C5 別途工事・確認事項

```
上の内訳に対して、次の2つのリストを作ってください。

(1) 別途工事 …… 本見積に含まない工事。後の追加交渉で揉めやすいものを優先して列挙
(2) 確認事項 …… 未測定・未確認のまま残っている事項。実測が必要なものを先頭に

(2) は、後で1つずつ潰していく作業リストとして使えるように書いてください。
```

## D3 見積改訂（rev管理）

```
旧版と新版の見積内訳を渡します。変更点の一覧を作ってください。

・追加された項目 / 削除された項目 / 数量が変わった項目 / 摘要が変わった項目 に分けること
・数量が変わった項目は、変更前 → 変更後 と、変更の根拠（実測したのか、条件が変わったのか）を併記
・発注者に送る「変更点のご説明」の文面も作ってください
```

## D4 契約書面の記載事項チェック

```
建設業法で請負契約書に記載が必要な事項について、チェックリストを作ってください。
そのうえで、渡した注文書・請書の内容が各項目を満たしているか、○/×/判断不能 で判定してください。

判断不能の項目は、なぜ判断できないか（記載がない/曖昧）を書いてください。
最終的な適法性の判断はしないでください。
```

## F1 施工計画書

```
次の工事条件から施工計画書のドラフトを作ってください。

構成：1.工事概要 / 2.施工条件 / 3.施工手順 / 4.安全管理 / 5.廃棄物処理 /
      6.本工事に含まないもの / 7.着工前に確定させる事項

・3.施工手順は表形式（順・作業・使用機材・留意点）
・4.安全管理は「リスク → 対策」の表で、この現場固有のリスクを優先すること
   （一般的な「整理整頓」のような項目は不要）
・7 には、まだ確定していない事項をすべて挙げること
・冒頭に「AI下書き・未監修」と明記すること

【工事条件】
（C3 で使った条件をそのまま貼る）
```

```

## I4 完了報告書

```
次の情報から完了報告書を作ってください。

構成：工事概要 / 実施した作業 / 数量の実績（見積比） / 使用した写真の一覧 /
      廃棄物の処理結果 / 特記事項

## J1 出来高・変更精算

```
当初見積と、現場で発生した変更記録（G6）を渡します。精算内訳を作ってください。

・当初見積の項目 / 当初数量 / 実績数量 / 増減 / 増減の根拠（変更記録のNo.）
・根拠となる変更記録が存在しない増減は、「根拠なし」として別欄に分けてください
・金額は、こちらが渡した単価のみを使うこと
```

## J5 原価集計・案件別粗利

```
案件の実績原価を集計して、粗利を出してください。

入力：協力会社への支払 / 直用の出面 / 機材リース / 運搬・処分費 / 諸経費
出力：工種別の原価、売上、粗利、粗利率

さらに、当初見積の内訳と突き合わせて、
「見積より原価が超過した工種」と「その超過額」を大きい順に並べてください。
```

## K1 実績歩掛の更新

```
J5 の実績と、当初見積の数量・想定工数を突き合わせて、歩掛の差分を出してください。

・工種 / 数量 / 見積時の想定工数 / 実績工数 / 差 / 差の率
・差が大きい工種について、考えられる要因の候補を挙げてください（断定はしない）

この結果は次回の見積単価に反映するので、単位を揃えて表で出してください。
```

## K4 コンテンツ化

```
この案件の記録から、記事の候補を3本挙げてください。

条件：
・「判断に迷った箇所」「想定と違った箇所」を含むものを優先すること。順調だった作業は記事にならない
・発注者名・所在地・関係者名・金額は使わないこと。寸法・数量・工種・判断の過程のみ
・各候補について、記事の見出し案（本編3〜5ブロック）まで出すこと
・`content/FORMAT.md` の記事＝台本フォーマットに沿うこと
```

## 使わないほうがいいプロンプト

参考までに、**実務で事故につながる指示**を挙げておく。

| 指示 | 何が起きるか |
|---|---|
| 「妥当な単価を教えて」 | 自社の歩掛と無関係な相場が入り、赤字か失注のどちらかになる |
| 「この材料は石綿含有ですか」 | 一般論が返る。判定は分析結果が決めること |
| 「届出は必要ですか」 | 規模要件と着工日で結論が反転する。所轄に訊く以外の正解がない |
| 「不明な箇所は適当に埋めて」 | 根拠のない数字が、実測値と同じ顔をして見積書に並ぶ |
| 「体験談風に書いて」 | ステマ規制とスパムポリシーの両方に抵触する |
